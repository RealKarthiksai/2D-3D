# 0017 Phase 9 object detector: EfficientDet-Lite0 (COCO), geometry-only fallback
Date 2026-11-16. Status: accepted under ADR 0018 item 6 (COCO furniture/obstacle classes only; doors/windows/mirrors come from geometry).
- Decision: use EfficientDet-Lite0 int8 TFLite (`efficientdet_lite0_detection.tflite`, 4.56 MB) from litert-community/efficientdet. Its card header says `license: apache-2.0`, "trained on COCO 2017", and "TFLite deployment of tensorflow/efficientdet/lite0/detection/1" (VERIFIED: https://huggingface.co/litert-community/efficientdet README.md and file list).
- Code licence: google/automl (EfficientDet source) is Apache-2.0 (VERIFIED: https://raw.githubusercontent.com/google/automl/master/LICENSE). MediaPipe code is Apache-2.0 (VERIFIED: https://raw.githubusercontent.com/google-ai-edge/mediapipe/master/LICENSE).
- Model family: COCO 80 labels only, no door/window/mirror; Lite0 int8 29.31 ms CPU on Pixel 6, input 320x320 for the MediaPipe build (VERIFIED: https://developers.google.com/edge/mediapipe/solutions/vision/object_detector). That page states no licence, so the MediaPipe-hosted files are NOT used; only the HF-carded file is.
- UNVERIFIED: COCO dataset terms (images carry Flickr terms; annotations believed CC BY 4.0; cocodataset.org terms page not readable via fetch); that litert-community is Google-run; that the HF file takes 320x320 int8 input and matches the 29 ms figure; any dedicated model card PDF for the Lite0 file (the guessed storage.googleapis URL returned 404).
- Rejected: SSD MobileNetV2 (MediaPipe, licence unstated), EfficientDet-Lite2 (70.91 ms int8 CPU, too slow), RT-DETRv2 and OWLv2 (no verified LiteRT export, OWLv2 too heavy; see research-ledger 2026-11-15), OID-v4 SSD (no licence or mobile build found).
- Consequence: phase9 step 10 proceeds with Lite0, behind a flag, with the NOTICE entry citing the HF card. If a human reading of COCO terms rejects redistribution of COCO-derived weights, drop to "detector dropped, geometry only" (no code change outside step 10).
